# Pod run plan — pillar-2 threshold sweep at scale, plus contrastive graphs

Written 2026-08-21, offline. Exploratory tier (ADR-0006): log every run in
`docs/run-log.md`, no PREREG needed, and nothing here may be cited for a pillar claim
however good it looks. Its job is to produce the effect-size estimate a later PREREG needs.

---

## The constraint that shapes everything

**A dictionary gates attribution graphs, and nothing else.** That distinction sets the whole
shape of the run, so it is worth stating precisely rather than as "we can only work at 4B".

| Instrument | Needs a transcoder set? | Usable at |
|---|---|---|
| Behavioural — sweep, flip point | no | any size |
| Activation patching / probing | no | any size that fits for inference |
| Attribution graphs | **yes** | 4B only |

`run_graphs_ct.py` builds a `ReplacementModel`: every MLP is swapped for a transcoder, and
the graph's *nodes are transcoder features* — `_completeness_from_json` scores influence
through `feature_type == "cross layer transcoder"` against error nodes. With no transcoder
set there are no nodes. Not a coarser graph, no graph; there is no degraded mode.

Two reasons that artifact stops at 4B:

1. **It has to be trained per model, per layer.** `mwhanna/gemma-scope-2-4b-it` covers the
   4B's 34 layers (hidden 2560, intermediate 10240) and works for both `gemma-3-4b-it` and
   `medgemma-4b-it` only because MedGemma 4B is built on the Gemma 3 4B architecture. Gemma 3
   12B and 27B are deeper and wider and have no published set. Note the direction of the
   dependency: the model was chosen downstream of the dictionary, not the reverse.
2. **Memory, if the first were ever solved.** 4B attribution already needs the whole H100
   80GB — nnsight holds all-layer activations and is not memory-efficient (`docs/ops.md`) —
   and `run_graphs_ct.py` is single-device with no sharding. A smaller tell that 4B is
   already near the edge: `_export_and_score` skips `graph.to_pt` because the raw `.pt`
   filled the disk.

So the run is three tracks, not two:

- **Track A — behavioural, every size.** `run_ecog_stimuli.py` needs no circuit-tracer, no
  nnsight, no transcoders; plain `AutoModelForCausalLM` forward passes, scales to 27B.
- **Track B — attribution, 4B only.** Where the dictionary exists and the memory envelope is
  known-good.
- **Track C — activation patching, every size.** `patch_grade.py`, no dictionary needed —
  this is how mechanism is reached at 12B/27B.

**Track A selects Track B's prompts.** The graphs are drawn at the vignettes where the sweep
has just shown an informative flip, so they explain a behaviour that was measured in the same
session rather than an arbitrary pair. That is what makes this one run and not two.

The size ladder is a **control, not an instrument upgrade**. Its job is to remove "the model
was too small" as an explanation for a negative pillar-2 result. It buys no circuit
resolution, and expecting it to is the misreading this section exists to prevent.

## Track A — the sweep

`specs/stimuli/ecog_sweep_v0.csv`, generated by `scripts/make_sweep_stimuli.py`. The 39
ecog_v0 vignettes crossed with six criteria — 234 rows, **no new clinical writing**.

| Criterion | Tier | Eligible | Purpose |
|---|---|---|---|
| `ECOG <= 1` | primary | 18/39 | common real protocol; pre-registered contrast |
| `ECOG <= 2` | primary | 30/39 | common real protocol; pre-registered contrast |
| `ECOG <= 0` | exploratory | 6/39 | rare protocol — a failure here may be off-distribution |
| `ECOG <= 3` | exploratory | 35/39 | rare protocol — same caveat |
| `ECOG <= 4` | ceiling | 39/39 | stuck-responder floor check; a No here is unambiguous |
| `ECOG >= 2` | direction | 21/39 | does the model read direction or pattern-match `<= 1`? |

Scored by `scripts/flip_point.py` on the **flip point** — the threshold where the model
switches Yes to No. The correct flip point is the vignette's true grade, so each vignette
yields one number and the five criteria per vignette are not pseudo-replication.

**Why this design and not more vignettes.** The 2026-08-06 pilot measured eligibility
between items on an unbalanced answer key, where a constant responder scores 0.56 — which is
exactly what Gemma scored. Getting a between-item result to clear that baseline needs 132-258
hand-written vignettes. Here a constant responder has no flip point at all: always-No scores
0/39, always-Yes scores 6/39 (it flips at t=0, so it collects the six true-grade-0 vignettes
for free). Against that baseline **11/39 already clears p<0.05**, and the 39 vignettes are
written. Clinician time is the bottleneck; this design spends none of it.

Read the score against the baseline, never alone — grade-0 vignettes are floored, so any
lenient responder collects them.

`flip_point.py --selftest` checks the scorer against perfect, always-Yes, always-No,
off-by-one and non-monotone responders. Run it before trusting a number.

### Models

Verify every id resolves before paying for a big pod:

```bash
python -c "from transformers import AutoConfig; [print(m, AutoConfig.from_pretrained(m).model_type) for m in [
  'google/gemma-3-4b-it','google/medgemma-4b-it',
  'google/gemma-3-12b-it','google/gemma-3-27b-it','google/medgemma-27b-text-it']]"
```

| Model | bf16 weights | Notes |
|---|---|---|
| `google/gemma-3-4b-it` | ~8.6GB | pilot baseline; also the Track B model |
| `google/medgemma-4b-it` | ~8.6GB | pilot baseline; also the Track B model |
| `google/gemma-3-12b-it` | ~24GB | the size step that matters most — same family, 3x |
| `google/gemma-3-27b-it` | ~54GB | multimodal checkpoint; needs `--device-map auto` |
| `google/medgemma-27b-text-it` | ~54GB | **id unverified.** Text-only, so the safer 27B |

The 12B/27B Gemma pair is the clean scaling comparison: same family, same tokenizer, same
prompt. The MedGemma 27B pairing is the domain comparison and is the one to drop first if
downloads run long — `medgemma-27b-text-it` is text-only where `medgemma-4b-it` is
multimodal, so it is not a clean size-only step from the 4B result anyway.

### Two gotchas that will cost a session if missed

**Disk.** ~150GB of checkpoints across five models. `docs/ops.md` records a pod whose
`/workspace` was only 50GB. Provision **200GB+**, or run in stages and clear the HF cache
between sizes. Decide before booting, not at the second download.

**System RAM.** Without `device_map` the weights stage through CPU RAM before `.to(device)`,
so the host needs as much free RAM as the checkpoint. Fine at 4B, wrong shape at 27B.
`--device-map auto` (added 2026-08-21) streams straight onto the GPU; use it for 12B and up.

### Commands

```bash
# offline first, on any machine — costs nothing, catches schema breaks
python scripts/run_ecog_stimuli.py --dry-run --stimuli specs/stimuli/ecog_sweep_v0.csv
python scripts/flip_point.py --selftest

# on the pod, per model
python scripts/run_ecog_stimuli.py --check-tokens --model $M     # tokenizer only, seconds
python scripts/run_ecog_stimuli.py --model $M \
    --stimuli specs/stimuli/ecog_sweep_v0.csv \
    --out data/ecog_sweep_v0_results_$(basename $M).json          # add --device-map auto at 12B+
```

`--check-tokens` per model is not optional. It downloads the tokenizer only and runs the
surface gate and separability check; a readout that resolves to the wrong surface form is how
the 2026-08-04 run produced `ecog_v0_results_READOUT_BUG.md`.

The grading prompt never mentions the criterion, so the six copies of a vignette must return
an identical grade. `flip_point.py` checks this and refuses to interpret a run where it
fails — free determinism check, no extra compute.

## Track B — contrastive attribution graphs at 4B

Pick 6 vignettes from the Track A 4B result that flip cleanly and correctly. For each,
attribute the **same vignette under two adjacent criteria** that straddle its flip point:
`ECOG <= g-1` (answer No) against `ECOG <= g` (answer Yes).

The vignette text is byte-identical across the pair. The only difference is one digit in the
criterion, and the answer inverts. Whatever differs between the two graphs is the threshold
comparison — the Application computation itself, isolated. That contrast is not available
from the Stage 1 graphs, where the criterion never moved.

Pick the 6 to span grades 1-3 (grade 0 has no `<= -1` partner, grade 4 has no clean upper
side) and to include at least two `inferred_symptoms` vignettes, since those are where the
Gemma paraphrase gradient bites.

```bash
python scripts/run_graphs_ct.py --smoke        # gemma-2-2b API check, do this first
python scripts/run_graphs_ct.py --model google/gemma-3-4b-it \
    --transcoders mwhanna/gemma-scope-2-4b-it
```

12 graphs for `gemma-3-4b-it`; repeat for `medgemma-4b-it` **only if time and disk allow** —
Stage 1's 32 graphs came to 1.1GB, so budget ~0.5-1.5GB here plus scp time. The Gemma set is
the one that must come back.

Completeness must be checked numerically before any graph is called valid (rule 5) —
`analyze_graphs.py`. Rendering in the frontend proves nothing.

## Track C — activation patching

`scripts/patch_grade.py`, written and verified offline 2026-08-21. Needs no dictionary, so
unlike Track B it runs at any size that fits for inference.

Take two vignettes with different true grades under the **same** criterion. Run the donor,
capture its residual stream at the final token position, inject that into the receiver at
layer L, read the eligibility logit. If the grade representation is what the answer is
computed from, the answer flips at some depth; if the answer is computed from something else,
it never does. That is most of the pillar-2 mechanistic claim, and it is available at 27B
where Track B is not.

Patching at the final position only — that is where the answer is read, and it is the one
position whose content is comparable across two prompts of different lengths.

The script refuses a pair whose criteria differ (that would confound grade with protocol) or
whose true grades match (nothing to transfer), and it does both checks *before* importing
torch, so a typo costs a second rather than a model load.

### Why it can be trusted without a GPU

`--selftest` builds a randomly initialised 3-layer Gemma 3 from config — no weights, no
network — and asserts two invariants that pin the hook mechanics:

- **identity** — patching a prompt with its own captured activations reproduces its logits
  exactly (observed delta 0.00e+00 at every layer)
- **dominance** — patching the *last* layer with the donor's activation reproduces the
  donor's logits exactly (7e-9), because everything downstream at that position is just the
  final norm and the unembed

Plus two guards: a layer-0 patch must *not* already equal the donor's logits, or the sweep
carries no depth information, and a plain forward afterwards must be unchanged, or a hook
leaked. It runs in ~10s and forces `HF_HUB_OFFLINE`, so it works on a plane.

```bash
python scripts/patch_grade.py --selftest
python scripts/patch_grade.py --model $M --pair E012_LE2:E001_LE2 \
    --out data/patch_ecog_$(basename $M).json      # --device-map auto at 12B+
```

**`interventions/patch.py` was not reusable.** It is CLT-era: `steer()` and `patch_feature()`
import `transformer_lens.HookedTransformer` and `clt.model.CrossLayerTranscoder`, so they
need exactly the dictionary that does not exist at 27B, on a backend the active path does not
install. The hook-and-return-logits shape was right; nothing else transferred.

**Decision status.** ADR-0004 rejected probing as a *replacement* for feature search — a
fitted direction is a weaker claim than a named ablatable feature. Patching as a complement,
at sizes where no dictionary exists, is not the question 0004 answered. Running it
exploratory needs nothing (ADR-0006), but a pillar claim resting on it needs that gap closed
first.

## Order of operations

Downloads dominate wall time, and Track A gates Track B, so the order is not arbitrary.

1. `setup_pod_circuit_tracer.sh` (this session runs attribution, so the full setup is needed).
   Then `run_graphs_ct.py --smoke`.
2. **4B sweep, both models, same session.** Small download, and it selects Track B's prompts.
3. Start the 12B and 27B downloads in a **tmux** pane while step 4 runs. SSH drops kill
   untmuxed runs.
4. `flip_point.py` on the 4B results → choose the 6 contrastive pairs.
5. **Track B attribution** on those pairs, `gemma-3-4b-it` first.
6. 12B and 27B sweeps as their downloads land (`--device-map auto`).
7. Housekeeping while the pod is up: regenerate `frontend/graph_data/elig_age_pos.json`
   (0 bytes) and copy back the MedGemma sweep JSON that was never retrieved.
8. scp everything back **before** terminating. Graphs are not in git — `frontend/` is
   gitignored, and two Stage 1 files exceed GitHub's 100MB limit.

Run both models of a size in the **same session**: dtype is derived from the device, and
splitting a pair across sessions puts a bf16/fp32 difference inside a comparison.

**Track C slots into step 6**, against each large model while its weights are already
resident. That is the only cheap moment for it — re-downloading 54GB to patch later doubles
the session cost. Run `patch_grade.py --selftest` once on the pod first; it takes 10s and
confirms the hook mechanics survived the torch version on that image.

## What would make this run a failure

- **Track A non-monotone at 4B.** If the answers do not form a step function, the flip point
  is not a meaningful quantity and Track B has nothing to explain. Stop and report that —
  it is a real result about whether the model treats a criterion as a threshold at all.
- **Grades differ across identical grading prompts.** Non-determinism invalidates the whole
  design. Stop and investigate before spending on 27B.
- **No transcoder set for 12B/27B.** Expected. Not a failure — it is the reason Track B is
  pinned at 4B, and it should be recorded rather than worked around. Confirm it and move on;
  do not spend session time hunting for one.

A flat or null flip-point result is a pre-registered null and does not need rescuing.

One outcome is worth naming in advance because it is the most likely awkward one: **the 27B
does the task and the 4B does not.** That is a good result, not a problem — it is a
capability threshold, and it is the case the size ladder was built to detect. It does leave
the mechanism at a size Track B cannot reach, and the answer to that is Track C, not a larger
transcoder. Record it and stop; deciding what to do about it is a separate call and probably
an ADR.
